# `:core` → `core.text` — структура текста

## Что внутри

`Rope` — персистентное дерево чанков. Публичные операции: `insert`, `delete`, `replace`,
`substring`, `charAt`, `appendTo`, `forEachChunk`, `lineOf`, `lineStart`, `lineEnd`.
Все правки возвращают новый `Rope`, старый остаётся валидным — на этом держатся и undo,
и снимки для фонового парсера.

## Почему так

Обоснование выбора — [ADR-005](../adr/ADR-005-text-core.md). Коротко: снимок за O(1) нужен
фоновому потоку подсветки, а хранение в UTF-16 избавляет отрисовку от декодирования.

Балансировка — AVL через операцию `join`: спускаемся по хребту до поддерева сравнимой высоты,
склеиваем, на обратном пути чиним баланс поворотами. `split` реализован через тот же `join`.
Это даёт O(log n) на правку в любом месте, включая худший случай — дописывание в конец,
на котором наивная склейка вырождает дерево в список.

## Где грабли

- **Суррогатные пары.** Офсеты — в UTF-16 code units, и офсет снаружи не должен попадать
  в середину пары. Внутренние разрезы за этим следят (`safeSplitPoint`), внешние — на совести
  редактора, который двигает курсор по графемам через `GraphemeBreaker`.
- **`lineEnd` и CRLF.** Возвращает офсет до переноса, отбрасывая и предшествующий `\r`.
  Если забыть про это, в конце каждой строки виндового файла будет висеть невидимый символ.
- **Размер листа.** `MAX_LEAF = 1024` — компромисс: меньше значит глубже дерево, больше
  значит дороже правка внутри листа (копируется весь чанк).
- **Линейные операции.** `toString()` и `substring` на всём документе копируют весь текст.
  Для сохранения файла есть `forEachChunk`, который не склеивает документ в одну строку.

## Тесты

`RopeTest` сравнивает rope с эталонным `StringBuilder` на 20 детерминированных
последовательностях по 300 правок и проверяет инварианты дерева (AVL-баланс, согласованность
накопленных длин и счётчиков переносов) после каждого шага. Упавший тест воспроизводится
запуском того же seed'а — «иногда падает на CI» здесь быть не может.
