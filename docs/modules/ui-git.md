# Панель git

`ui/vcs/GitPanel.kt`, тесты — `ui/src/jvmTest/.../vcs/GitPanelTest.kt`.
Сам репозиторий живёт в `:vcs` (`vcs-git.md`), вкладка собирается в `app/desktop`.

## Граница

`:ui` не имеет права зависеть от `:vcs` — это проверяется `checkArchitecture`.
Поэтому у панели свой перечень `ChangeKind`, а точка сборки переводит в него
`FileStatus` из `:vcs`. Ровно как с пометками гаттера, и по той же причине:
интерфейсу незачем знать про git, он рисует буквы и пути.

Цена честная: два одинаковых перечня в разных модулях, и при добавлении третьего
состояния их придётся править вместе. Компилятор об этом не напомнит — напомнит
`when` без ветки в переводчике, который падает на сборке.

## Панель ничего не делает сама

Ни чтения статуса, ни коммита: она показывает переданное и зовёт обратные вызовы.
`status()` — это обход рабочей копии, `commit()` — запись в хранилище; на главном
потоке им делать нечего, а панель живёт именно там.

## Индекса здесь нет

«Зафиксировать» добавляет всё изменённое и коммитит. Частичный индекс — это своя
половина интерфейса: галочки у файлов, разница между «в индексе» и «в рабочей
копии», понятие staged hunk. Нужен он тому, кто уже знает git настолько, что
откроет консоль. Цена названа, чтобы не выглядело недоделкой: коммит здесь всегда
«всё, что изменено».

## Чего панель не даёт сделать, и почему это главное

Коммит — запись в историю, которую потом никто не перепишет. Поэтому проверок
четыре, и каждая закреплена мутацией:

| Не даёт | Потому что |
|---|---|
| коммит без сообщения | пустое сообщение в истории бесполезно навсегда |
| коммит без автора | коммит от выдуманного автора видно годами |
| коммит без изменений | нечего фиксировать — значит кнопка не должна делать вид |
| второй коммит поверх идущего | двойное нажатие не должно давать два коммита |

**Причина написана рядом с кнопкой.** Серая кнопка без объяснения читается как
«сломалось», а не как «не хватает вот этого». Текст результата последнего коммита
важнее подсказки и вытесняет её: он отвечает на вопрос «получилось ли».

**Сообщение подрезается и очищается после коммита.** Пробелы по краям живут в
истории вечно; неочищенное поле уедет в следующий коммит, и заметить это можно
будет уже только в `git log`.

## Про подпись говорится вслух

JGit не ставит ssh-подписи, а `commit.gpgsign=true` — частая настройка. `:vcs`
коммитит без подписи и сообщает, что подпись просили (`vcs-git.md`); вкладка
дописывает это в строку результата. В репозитории с обязательной подписью такой
коммит отклонят на сервере, и узнать об этом лучше сразу.

## Автор берётся из настроек git

`GitRepository.identity()` читает `user.name` и `user.email`. **JGit наследует
пользовательский `~/.gitconfig`** — это выяснилось не из документации, а из
упавшего теста: первая его редакция ждала `null` для репозитория без настроек и
получила почту из глобальных. Поэтому тест проверяет пустое значение, а не
отсутствующее: на машине с настроенным git отсутствующего не бывает.

На Android домашней конфигурации обычно нет вовсе, и там интерфейсу придётся
спрашивать имя самому. Пока панели на телефоне нет — не потому, что её сложно
показать, а потому, что репозиторию неоткуда взяться: клонирования нет, а
`git init` из интерфейса не сделать. Заводить панель раньше этого значит показать
человеку экран, на котором написано «нет репозитория», и всё.

## Проверено

Снимком экрана против настоящего репозитория этого проекта: ветка, автор из
конфигурации, шесть изменённых файлов с верными буквами статуса и подсказка
«нужно сообщение коммита». Восемь мутаций в панели, восемь падений.
