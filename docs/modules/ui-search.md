# Поиск и замена

`core/editor/SearchSession.kt`, `ui/search/SearchBar.kt`

## Разделение

`TextSearch` (`:core`) знает про регулярные выражения и ничего — про курсоры.
`EditorState` знает про курсоры и ничего — про поиск. `SearchSession` — место,
где они встречаются: держит запрос, водит курсор по совпадениям, заменяет.

## Решения и их цена

**Совпадения не собираются в список целиком.** На файле в десять мегабайт это
сотни тысяч объектов на каждое нажатие в строке поиска. Для подсветки берётся
только видимый кусок (`matchesIn`), для подписи — счёт с потолком в 500.
Достигнутый потолок видно: интерфейс пишет «больше 500», а не врёт точным
числом.

**«Дальше» ищет от конца текущего совпадения, а не от курсора.** Иначе после
первого нажатия кнопка находит то же самое, и выглядит это как сломанный поиск.
«Заменить» по той же причине переходит к следующему.

**Замена всех — одна правка.** Иначе откат замены по файлу превращается в сотню
нажатий undo.

**Юникодные классы символов включены** (`(?U)`). Без этого `\w`, `\d`, `\b` в
выражении пользователя не видят кириллицу: `имя: (\w+)` по русскому тексту не
находит ничего. Человек пишет такое выражение, зная Python, где `re` работает
наоборот.

Чего этот флаг **не** чинит, вопреки первому впечатлению: поиск без учёта
регистра по кириллице работает и без него. Ошибочный вывод получился из-за
пробы на Java, скомпилированной с неверной кодировкой исходника — «ШАГ» и «Шаг»
там превратились в разный мусор. Ровно та же ловушка, что с именами файлов.

**Подстановка групп — одна реализация на замену одного совпадения и всех.**
Осторожно с нумерацией: в `SearchMatch.groups` нулевой группы нет, а `$1`
означает первую скобочную, то есть `$N` это `groups[N - 1]`. Ошибка на единицу
здесь даёт пустую строку вместо найденного текста, и она уже случилась.

## Интерфейс

Поля ввода — `BasicTextField`, и это не противоречит ADR-001. Его отвергли для
редактора кода, где текст в мегабайты и нужна виртуализация; строка поиска —
десяток символов в одну строку, ровно то, для чего он сделан.

Кнопки — через `pointerInput`, а не `clickable`: `clickable` забирает фокус, а
вместе с ним уходит курсор из поля ввода.

Подсветка совпадений рисуется тем же кодом, что и выделение
(`drawRange` в `CodeEditor`): правило «диапазон, захвативший перенос, тянется до
края экрана» одно на двоих, и разъезжаться ему незачем.

## Чего нет

Поиска по проекту — он требует индекса, которого пока нет (см.
`docs/modules/core-project.md`). Истории запросов. Подсветки текущего совпадения
цветом, отличным от остальных: сейчас его видно по выделению.
