# Графика в коде пользователя

`runner/android/src/main/python/eide.py` — шим,
`native/canvas` — кадровый буфер под ним ([разбор](native-canvas.md)).

## Как это выглядит из программы

```python
import eide

canvas = eide.canvas()
clock = eide.Clock()
x = 0

while True:
    canvas.clear(0x101010FF)
    canvas.fill_rect(x, 300, 80, 80, 0xFF3B30FF)
    canvas.present()
    x = (x + 4) % canvas.width
    clock.tick(60)
```

Соединение уже установлено к моменту запуска: искать и открывать нечего.

## Решения и их цена

**ctypes, а не C-расширение.** Расширение пришлось бы пересобирать под каждую
версию Python; `.so` через ctypes переживает обновление интерпретатора.
Цена: вызов ctypes стоит микросекунды, поэтому попиксельного API здесь нет и не
будет — примитивы обязаны быть батчевыми (ADR-004). `fill_rect` в цикле по
пикселям будет медленным, и это свойство схемы, а не недоработка.

**Параметры канвы приходят через окружение** (`EIDE_CANVAS_*`), а не аргументами
скрипта: аргументы принадлежат программе пользователя, занимать их служебным
нельзя. Адрес передаётся числом, потому что отображением занимается Kotlin
(`SharedMemory`), а ctypes умеет работать только с числом.

**Кадр начинается сам, заканчивается явно.** Первый рисующий вызов открывает
кадр, `present()` его публикует. Одно понятие вместо двух; неопубликованный
кадр IDE просто не увидит — она показывает последний целый.

**`eide.available()` вместо падения.** Программу могли запустить без графики.
Пусть она узнает об этом сама, а не упадёт на ровном месте.

**`Clock.tick` не спрятан внутрь `present`.** Скрытый сон — сюрприз; а без
ограничителя цикл крутится на полной скорости, греет телефон и не даёт ничего:
IDE всё равно показывает не чаще, чем обновляется экран. Поэтому он есть, но
его видно.

## Проверка

`./gradlew canvasShimTest` — шим гоняется на десктопе против настоящей
`libeide_canvas.so`. ctypes не знает, что он на Android: та же библиотека
собирается на хосте. Иначе опечатка в порядке аргументов ловится только на
телефоне и выглядит как «просто не рисует».

Тесты доведены мутациями. Ловятся: переставленные каналы цвета, незакрытый
кадр, неоткрытый кадр, неработающий ограничитель частоты, переставленные
местами координаты и размеры прямоугольника.

**Ловушка, стоившая получаса.** Инвалидация `.pyc` в Python идёт по времени
изменения и размеру файла. Мутация того же размера, внесённая в ту же секунду,
остаётся невидимой: интерпретатор берёт кэш от предыдущей версии. Поэтому
проверка гоняется с `PYTHONDONTWRITEBYTECODE=1`, и это не про чистоту.

## Чего нет

Линий, спрайтов, текста, ввода. Для этапа 1 нужен движущийся квадрат — `clear`
и `fill_rect` его рисуют. Ввод (тач как мышь) идёт кольцевым буфером в той же
разделяемой памяти и появится вместе с уровнем 3 из ТЗ.
