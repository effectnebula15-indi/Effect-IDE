# `:ui` → `ui.editor` — отрисовка текста

## Что внутри

- `CodeEditor` — единственный рендерер: гаттер, текст, выделение, курсоры,
  подсветка совпадений поиска. Рисует только видимые строки поверх `Rope`.
- `LineLayoutCache` — двухпоколенный кэш разметки строк.
- `LineStates` — состояния лексера перед каждой строкой (см. `core-syntax`).
- `FrameMeter` — счётчик кадров для замеров.
- `FontZoom` — изменение размера шрифта двумя пальцами.
- `AutoSave` — запись буфера после паузы в наборе.
- `RenderProbe` — крючок для замеров: автопрокрутка и счётчики кэша.
- `RenderBenchmark` — стенд прототипа P2, общий для Android и десктопа.

Как редактор проверяется без экрана — в `ui-testing.md`.

## Почему так

**Виртуализация.** Документ может быть любого размера, а на кадре трогается только то,
что видно. Ни `Text` на строку, ни список composable-узлов: один `Canvas` и цикл по
видимому диапазону. Это единственный способ не платить за длину файла.

**Кэш по тексту строки, а не по номеру.** Вставка строки в начало файла сдвигает номера
всех последующих, но их содержимое не меняется. Ключ по тексту сохраняет разметку там,
где ключ по номеру выбросил бы весь кэш.

**Двухпоколенное вытеснение вместо LRU.** У LRU есть операции, зависящие от размера кэша,
и они дают всплеск на отдельном кадре — ровно то, ради устранения чего кэш и заводился.
Здесь при переполнении молодое поколение просто становится старым. Грубее, зато
предсказуемо по времени.

**Счётчик просадок, а не средний fps.** Средние 58 fps с одним кадром по 200 мс выглядят
прилично в отчёте и отвратительно на экране.

**Автосохранение считает версии документа, а не ревизии редактора.** Ревизия растёт
и от движения курсора. Пока считались ревизии, было две беды сразу: файл переписывался
на диск после каждого тыка в текст (на телефоне это износ флеш-памяти и сбитое время
изменения файла), и — хуже — пауза отсчитывалась заново, то есть человек, водивший
курсором по уже набранному тексту, откладывал запись своих правок на всё это время.

Решение о том, когда писать, вынесено из composable в `saveSignals`: паузы в стенде
Compose идут по настоящим часам, а обычным flow-тестом с виртуальным временем то же
самое проверяется точно и без ожиданий. Это не украшение кода, а единственный способ
проверить поведение, которое целиком состоит из пауз.

**Зум написан вручную, а не через `detectTransformGestures`.** Готовый детектор
срабатывает и на одном пальце и забирает себе обычную прокрутку. Здесь события
трогаются только когда пальцев два, поэтому прокрутка одним пальцем проходит мимо
нетронутой — на это есть отдельный тест.

**Размер шрифта живёт в оболочке приложения, а не в редакторе.** Он переживает
смену файла и уход в дерево: человек настраивает его один раз. Между запусками
приложения — не переживает: хранилища настроек нет, и заводить его ради одного
числа рано.

**Курсор встаёт между знаками, а не в знак.** Тычок в левую половину знака ставит
курсор перед ним, в правую — после. Это не мелочь для теста: тычок ровно в середину
знака даёт ответ, неоднозначный по определению, и утверждения строятся по четвертям.

**Гаттер рисуется отдельно от текста.** Текст едет по горизонтали и обрезается по
границе гаттера, гаттер стоит на месте: столбец номеров, уезжающий вместе с текстом,
перестаёт быть ориентиром.

**Стенд замеров рисует настоящий редактор.** Сначала у стенда был свой упрощённый
рендерер: без гаттера, курсоров и подсветки. Он отстал от редактора в первую же неделю,
и замер начал описывать код, которого пользователь не видит. Теперь стенд гоняет
`CodeEditor`, а всё, что нужно только для замера, живёт в `RenderProbe` — параметре,
который в обычной работе равен `null`. Цена названа прямо: в редакторе есть параметр,
которого его логика не требует. Выгода видна сразу — на первом же прогоне
консолидированный стенд поймал падение в `LineStates`, которого упрощённая копия
поймать не могла: она не подсвечивала.

## Где грабли

- **Высота строки считается один раз.** Это верно, пока шрифт моноширинный и переноса
  строк нет. Появится перенос — придётся считать высоту на строку, и вся арифметика
  прокрутки станет другой.
- **Строка размечается целиком, без ограничения ширины.** Иначе Compose переносит
  длинную строку, а рисуется она всё равно на одной высоте — хвост ложится поверх
  следующей строки. Так и было, пока файл с 456-значной строкой не попал на снимок
  экрана. Цена нового поведения: разметка длинной строки стоит по её длине,
  и файл из одной строки в мегабайт будет заметно тормозить на первом показе.
- **Граница горизонтальной прокрутки — самая широкая строка, которую довелось
  разметить.** Настоящий максимум по документу стоил бы прохода по всему файлу на
  каждый кадр. Отсюда следствие: побывав на длинной строке, вправо можно уехать
  в пустоту и на коротких.
- **Разметка строки — один объект на всех потребителей**: рисование, попадание тапа
  и прокрутка за курсором берут её из одного и того же кэша. Пока арифметик было две
  (по разметке при рисовании, по ширине цифры при тапе), курсор на строке с
  табуляцией или иероглифом вставал не туда, куда ткнули — поймано тестом
  `a tap lands on the character it points at`. По ширине цифры считается только
  ширина гаттера: там одни цифры, и это верно по построению.
- **`FrameMeter` включает непрерывную перерисовку.** Пока замер идёт, приложение рисует
  кадры постоянно и жжёт батарею. Это инструмент, а не режим по умолчанию.
- **Первый кадр дорогой** — на десктопе 241 мс с подсветкой и 125 мс без неё.
  В прокрутке это не видно, но попадает в бюджет холодного старта.
- **Кэш разметки живёт вместе со стилем.** Ключ в нём — текст строки, поэтому
  разметка, снятая при другом размере шрифта, нашлась бы по тому же ключу снова.
  Пока кэш был вечным, смена размера меняла картинку, но не разметку: тап уезжал,
  а стенд P2 для другого размера показывал цифры прежнего. Проверяется тестом
  `a bigger font moves the same point to an earlier column` — и он, кстати, сперва
  проходил по неверной причине: со старой разметкой колонка тоже немного
  уменьшается, потому что гаттер стал шире.
- **Ввод отключается при замерах.** Не ради экономии узлов: сессия ввода поднимает на
  телефоне клавиатуру, та закрывает половину строк, и кадр обходится дешевле, чем
  в работе. Замер с клавиатурой льстил бы.

## Шрифт

JetBrains Mono (OFL 1.1), вариант **NL** — без лигатур, два начертания:
обычное и жирное.

Лигатуры выключены не по вкусу. Обычный JetBrains Mono рисует `>=` как `≥`, а
`!=` как `≠`: в тексте одно, на экране другое. Учащемуся это мешает прямо, и
IntelliJ сам поставляется с выключенными лигатурами. Когда появятся настройки,
это станет переключателем. Остальные весят по
четверти мегабайта каждое и понадобятся не раньше подсветки, которая ими
различает.

Файлы лежат в `assets/fonts/` в корне репозитория, а не скачиваются на сборке,
как CPython. Причина в размере: полмегабайта в git — не двадцать два, а
отсутствие ещё одной сетевой зависимости в сборке дороже. Рядом лежит `OFL.txt`
— того требует лицензия, и он же едет в APK.

Каталог один на оба приложения: копия для каждого рассинхронизировалась бы при
первом же обновлении. Android подключает его через `addStaticSourceDirectory`,
десктоп — через `resources.srcDir`.

Само семейство подставляется снаружи, через `LocalEditorFont`: на Android
шрифт грузится из assets, на десктопе — из ресурсов classpath, и это разные
API. Держать в `:ui` две реализации ради двух строчек дороже, чем передать
готовое семейство из точки сборки.

Значение по умолчанию — системный моноширинный. Это не заглушка «на потом»:
если файл не прочитается, редактор обязан остаться читаемым.
