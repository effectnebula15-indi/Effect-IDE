# `:ui` → `ui.run` — панель вывода программы

## Что внутри

`OutputPanel` — текст, который пишет запущенная программа: stdout, stderr и строка
о завершении.

## Обещание, у которого две половины

Панель доезжает до конца, когда приходят новые строки, и **не** дёргает того, кто
отлистал назад читать трассировку. По отдельности каждая половина тривиальна, вместе —
источник ошибок.

Признак «следим за концом» переключается **только по окончании настоящей прокрутки**:
важен переход «крутили → перестали», а не само состояние. Своя программная прокрутка
даёт такой же переход и оставляет слежение включённым, потому что заканчивается ровно
в конце.

## Почему не проще

Две предыдущие редакции спрашивали «а был ли человек внизу» в момент прихода текста:

```kotlin
val wasAtBottom = remember(text) { scroll.value >= scroll.maxValue - THRESHOLD }
```

Это не работало **никогда**. До первой раскладки `ScrollState.maxValue` равен
`Int.MAX_VALUE`; сравнение с ним даёт «не внизу», и признак застревал в этом значении
навсегда. Панель оставалась на первой строке, сколько бы программа ни писала.

Диагноз получен не рассуждением, а печатью значений из работающего приложения:
`len=0 value=0 max=2147483647`. Два предположения до этого были неверными, и оба
выглядели убедительно.

## Чего тесты не показали

Стенд Compose эту ошибку не ловит и поймать не может: `waitForIdle()` возвращается
после раскладки, и в тесте начальный `maxValue` — настоящий ноль (замерено: `(0.0, 0.0)`).
Момент «эффект выполняется между сборкой и раскладкой», в котором всё и ломалось,
в стенде не наблюдаем.

Поэтому здесь нет теста «панель следит за концом на самом деле» — есть тест на то, что
она доезжает до конца при новых строках, тест на то, что отлиставшего назад не утаскивает
обратно, и **снимок экрана десктопной сборки** как единственное доказательство, что
починено именно то, что было сломано.
