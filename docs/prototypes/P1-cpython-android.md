# P1. CPython в отдельном процессе на Android

Прототип закрывает риск **R2** из [дорожной карты](../plan.md): «CPython под Android arm64
не достаётся дёшево». Он же проверяет ADR-002 (отдельный процесс) и протокол из ADR-003
на настоящем железе.

## Что выяснилось на этапе разведки

Главное: **городить ничего не нужно**. Android — официально поддерживаемая платформа
CPython, и python.org публикует готовую сборку под arm64 в каждом релизе:
`python-3.14.7-aarch64-linux-android.tar.gz`, 22 МБ, с подписями.

Отсюда следствия, которые меняют план в лучшую сторону:

- **Chaquopy и python-for-android не нужны.** Ни лицензионных вопросов, ни чужой
  процессной модели, ни зависимости от чужого расписания релизов.
- **`_ctypes` есть в поставке.** На нём держится графический шим (ADR-004): без него
  пришлось бы собирать C-расширение под каждую версию Python.
- **Ограничение W^X нас не касается** на этом пути. Запрет Android касается `exec`
  файлов из каталога данных, а не `dlopen` библиотек: расширения Python из `lib-dynload`
  официальная документация предписывает распаковывать на диск и грузить оттуда.
- **Минимальный API у сборки — 24**, наш minSdk 27 выше.

Размеры (замерено на собранном debug-APK):

| Часть | Распакованно | В APK |
|---|---|---|
| dex (Kotlin + Compose, **без R8**) | 22.4 МБ | 8.5 МБ |
| нативные `.so` в jniLibs | 11.7 МБ | 11.7 МБ |
| расширения Python (`lib-dynload`) | 7.3 МБ | 7.3 МБ |
| стандартная библиотека (`.py`) | 9.6 МБ | 2.9 МБ |
| **итого APK** | | **~32 МБ** |

Бюджет из плана — 60 МБ, и это ещё debug-сборка без сжатия кода. Из stdlib уже выкинуты
`test` (37 МБ!), `idlelib`, `ensurepip`, `tkinter`, `pydoc_data`, `turtledemo`.

## Что собрано

- `:runner:android` — библиотека с нативным мостом и сервисом раннера.
  Сервис объявлен с `android:process=":runner"`, то есть исполняется в отдельном процессе.
- `:app:android` — приложение-прототип: поле ввода, кнопка Run, панель вывода.
- Канал между процессами — пара сокетов из `ParcelFileDescriptor.createSocketPair()`,
  переданная сервису через Intent. Не abstract-namespace unix-сокет и не порт на loopback:
  и то, и другое на Android видно другим приложениям.
- Поверх канала идёт тот же протокол `[u32 длина][u8 тип][payload]`, что и в `:core`.

**Это не редактор.** Ввод на `BasicTextField` намеренно: своё ядро отрисовки — этап 1.

## Чего в прототипе нет

Кнопки Stop и проверки убийства зависшего процесса — это отдельный прототип **P4**.
Здесь проверяется только запуск и доставка вывода.

## Как проверить (нужен телефон)

Собрать и поставить:

```bash
./gradlew :app:android:assembleDebug
adb install -r app/android/build/outputs/apk/debug/android-debug.apk
adb logcat -c && adb logcat -s eide.runner
```

APK также лежит в артефактах сборки CI, если собирать локально нечем.

### Чек-лист

1. **Приложение запускается**, видно тёмный экран с кодом и кнопкой Run.
2. **Run печатает вывод.** Ожидается что-то вроде:
   `Python 3.14.7 на aarch64`, затем пять строк `шаг N`, затем `готово`
   и `[процесс завершился с кодом 0]`.
   Если вместо этого пусто, а в logcat видно вывод Python — значит не сработала
   переброска `sys.stdout` из logcat в наш канал, и это чинится в `eide_python.c`.
3. **Процесс действительно отдельный.** Во время работы программы:
   ```bash
   adb shell ps -A | grep effectnebula
   ```
   должно быть **две** строки: основной процесс и `...:runner`.
4. **Первая распаковка stdlib.** В logcat строка `stdlib распакована за N мс`.
   Записать N: это разовая цена первого запуска, и если она в секундах — надо
   переходить на zip вместо тысяч мелких файлов.
5. **Второй запуск не распаковывает заново** — строки в logcat быть не должно.
6. **Ошибка попадает в stderr.** Заменить код на `1/0`, ожидается traceback в панели
   вывода и ненулевой код возврата.
7. **Холодный старт приложения** (после `adb shell am force-stop io.github.effectnebula.eide`).
   Цель из плана — 1.5 с. Python при старте IDE не поднимается, так что старт должен
   быть быстрым; если нет — виноват Compose, и это уже риск R3.
8. **Память в покое:**
   ```bash
   adb shell dumpsys meminfo io.github.effectnebula.eide | head -20
   ```
   Цель — 250 МБ. На флагмане цифра будет приятной и ни о чём не скажет: настоящая
   проверка — на слабом устройстве.

### Что сообщить обратно

Достаточно: пункты чек-листа (прошло / не прошло), время распаковки, время холодного
старта, цифру RSS и — если что-то упало — вывод `adb logcat -s eide.runner AndroidRuntime`.

## Честно о статусе

Ничто из перечисленного **не проверено на устройстве**: в среде, где это собиралось,
нет ни телефона, ни эмулятора (нет `/dev/kvm`). Проверено ровно то, что проверяется без
устройства: проект собирается, нативный код компонуется с `libpython`, lint проходит,
APK собирается и его состав измерен.

Lint по дороге поймал две настоящие ошибки, которые иначе вылезли бы только на телефоне:
класс активности в манифесте не резолвился, и вызов `Context.getMainExecutor` требует
API 28 при нашем minSdk 27.
