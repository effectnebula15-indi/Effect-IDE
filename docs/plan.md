# Дорожная карта

Оценки — календарные недели при 5–10 часах владельца проекта в неделю. Узкое место — не
написание кода, а ревью и проверка на устройстве. Это оценки, а не обязательства.

## Зафиксированные вводные

| Вопрос | Ответ |
|---|---|
| Цель v1 | Python + графика на телефоне |
| Первый бэкенд исполнения | встроенный CPython в отдельном процессе |
| iOS / web | не поддерживаются, в решениях не учитываются |
| Графика | собственный Canvas API, не совместимость с pygame |
| Размер файлов | до 10 МБ целиком в памяти |
| Нативные части | на C (CMake + NDK) |
| Десктоп | собирается с первого этапа |
| Тестовое устройство | флагман, 12+ ГБ, Android 13–16 |

Действующие допущения: исполняем только свой код (песочница ради предсказуемости, не
безопасности); в v1 панель вывода, а не shell; удалённый бэкенд — ПК в той же Wi-Fi;
полный C++-LSP только через ПК; git локальный; тема своя «в духе Darcula»; лицензия Apache-2.0.

## Этап 0. Разведка (прототипы)

Три неизвестных закрываются измерением, а не рассуждением. Код прототипов пишется здесь,
**запускается на телефоне владельцем проекта**.

- **P1 — собран, ждёт проверки на устройстве.** Источник CPython выяснен: официальная
  сборка с python.org, Chaquopy и python-for-android не нужны. APK собирается, его состав
  измерен (32 МБ в debug при бюджете 60). Чек-лист проверки — в
  [docs/prototypes/P1-cpython-android.md](prototypes/P1-cpython-android.md).
- **P2 (1–2 дня).** Compose-экран с виртуализацией строк и кэшем разметки; замер jank при
  флинг-скролле (`dumpsys gfxinfo`).
- **P3 (1 день).** Два процесса одного APK, передача файлового дескриптора через `LocalSocket`,
  mmap с обеих сторон, атомарный счётчик.
- **P4 (1 день, в начале этапа 1).** Раннер исполняет `while True: pass` и бесконечный рост
  списка; IDE обязана это пережить, раннер — умереть предсказуемо.

## Этап 1. Живая сборка — тонкий вертикальный срез (3–5 недель)

Срез проходит через все слои сразу, а не делает один слой целиком: смысл в том, чтобы
доказать работоспособность архитектуры от нажатия кнопки до пикселя на экране.

- Android APK и Desktop собираются из одного репозитория, ставятся, стартуют
- Открыть папку как проект, дерево файлов, открыть `.py`
- Редактор: собственный рендер, JetBrains Mono, виртуализация строк, курсор, ввод,
  выделение, undo/redo с группировкой, сохранение, тёмная тема
- На Android — дополнительный ряд клавиш (Tab, Esc, стрелки, скобки, `:`)
- Run: исполнение в отдельном процессе через CPython, stdout/stderr в нижнюю панель,
  Stop реально убивает зависший процесс
- Минимальный canvas: `clear`, `fill_rect`, `present`, без событий ввода
- Автосохранение буферов при уходе в фон

Нет: подсветки, автодополнения, git, поиска, ввода в графике.

**Готово, когда:** на телефоне написан скрипт с движущимся квадратом; Run показывает его на
весь экран; свайп возвращает к коду, программа продолжает идти; Stop останавливает.
Размер APK и холодный старт измерены.

## Этап 2. Редактор становится пригодным (3–4 недели)

tree-sitter с инкрементальным парсингом в фоне, подсветка, поиск и замена с regex,
множественные курсоры, свёртка, форматирование, позиционирование курсора пальцем,
двухпальцевый зум шрифта, свайп между файлами.

**Готово, когда:** скролл держит 60 fps на файле в 5000 строк, и час работы на телефоне
не вызывает желания его выбросить.

## Этап 3. Графика по-настоящему (2–3 недели)

События ввода (тач как мышь, экранная и внешняя клавиатура), `blit`, спрайты, текст,
ландшафт, стабильный кадровый темп.

**Готово, когда:** змейка или понг на Python идут 60 fps, управление тачем работает.

## Этап 4. Проект и навигация (3–4 недели)

Git через JGit (статус в гаттере, diff, commit, ветки), поиск по проекту, палитра команд,
вкладки, breadcrumbs, внешняя клавиатура и мышь на Android, keymap IntelliJ.

**Готово, когда:** реальный проект ведётся в git не выходя из IDE.

## Этап 5. Интеллект (4–6 недель)

LSP-клиент, pylsp локально (влезет ли — проверяется отдельно), автодополнение, переход к
определению, ошибки в гаттере, урезанный режим по индексу проекта.

**Готово, когда:** автодополнение отвечает быстрее 300 мс на файле среднего размера.

## Этап 6. Удалённый бэкенд (3–4 недели)

Тот же протокол поверх WebSocket, синхронизация файлов, поведение при обрыве.
Здесь появляется настоящий C/C++ и clangd — без порта LLVM под Android.

**Готово, когда:** тот же Run с переключателем «на ПК», C++-файл компилируется и запускается.

## Этап 7. Отладчик (4+ недели)

DAP-клиент, debugpy для Python: точки останова, шаги, переменные.

**Готово, когда:** остановка на breakpoint на телефоне с просмотром переменных.

## Дальше, без оценок

WASM-бэкенд с настоящей песочницей; локальный C через TCC (у него нет C++ и слабая
оптимизация, а на Android он должен генерировать машинный код в исполняемой анонимной
памяти — разрешено ли это обычному приложению на всех устройствах, надо проверять).

Ориентир по срокам: до состояния «пригодная IDE с подсветкой, графикой и git» — порядка
полугода. Нативный Clang на устройстве в этот горизонт не входит.

## Реестр рисков

| Риск | Вероятность / ущерб | Чем закрывается |
|---|---|---|
| Проект будет заброшен | высокая / смертельный | каждый этап заканчивается тем, что можно показать; движущийся квадрат на телефоне примерно через месяц |
| ~~CPython под Android не достаётся дёшево~~ | **снят разведкой** | официальная сборка с python.org; остался вопрос поведения на устройстве |
| Свой рендер текста не держит 60 fps | средняя / высокий | прототип P2; провал означает пересмотр ADR-001 |
| Передача разделяемой памяти между процессами | средняя / средний | прототип P3; запасной путь — Binder/AIDL для дескриптора |
| Лимиты и убийство раннера ведут себя не так | средняя / средний | прототип P4; запасной путь — watchdog по RSS снаружи |
| Нативные библиотеки под три десктопные ОС | высокая / средний | матрица ОС в CI |
| Потеря контекста между сессиями разработки | высокая / средний | ADR и план лежат в репозитории, решения — в коммитах |
| Нефункциональные цели не выполняются | средняя / низкий | замеры в CI; RSS мерить на слабом устройстве, не на флагмане |

## Антицели v1

Маркетплейс плагинов, совместная работа в реальном времени, десятки языков, встроенный
ИИ-ассистент, эмуляция полноценного Linux-окружения, сборка Android-приложений внутри IDE.
