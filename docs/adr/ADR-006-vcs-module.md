# ADR-006. Git живёт в отдельном модуле `:vcs`

## Контекст

Плану нужен git: статус в гаттере, дифф, коммит, ветки (этап 4). Первоначальная схема
из Шага 3 помещала его в `core/project`. Но правило проекта гласит, что `:core` знает
только Kotlin stdlib и kotlinx, и правило это не формальное.

## Почему не в `:core`

- **JGit тянут все, кому нужен `:core`.** В том числе процесс-раннер, которому git
  не нужен вообще. Раннер должен стартовать быстро и занимать мало — лишние мегабайты
  библиотеки в нём это прямая цена в холодном старте запуска программы.
- **Правило «только stdlib» защищает от расползания.** Один раз впустив тяжёлую
  библиотеку «по делу», дальше её впускают уже по привычке.
- **Реализацию git мы, возможно, поменяем.** JGit на Android — известная зона риска
  (см. ниже). Отдельный модуль с узким интерфейсом делает замену дешёвой.

## Решение

Модуль `:vcs` — обычный Kotlin/JVM, как `:core`, зависит от `:core` и от JGit.
`:core` про git не знает. Правило зависимостей в корневом `build.gradle.kts` дополнено,
а `CLAUDE.md` обновлён: граница изменена явно, а не обойдена в модуле.

## Почему JGit, а не вызов git

Вызывать системный `git` на Android нечем: его там нет, а положить свой бинарник мешает
запрет на исполнение файлов из каталога данных (ADR-003). JGit — чистая Java, ей это
безразлично.

## Риск, который надо проверить на устройстве

JGit местами пользуется `java.nio.file`, который на Android появился только с API 26.
Наш minSdk 27 формально выше, но отдельные части JGit исторически вели себя на Android
не так, как на настольной Java — например, при определении атрибутов файловой системы.

Проверить это можно только запуском на телефоне. Пока не проверено, считаем работу
git на Android **неподтверждённой**, и именно поэтому интерфейс `:vcs` держим узким:
если JGit не заработает, менять придётся один модуль, а не весь редактор.

## Что мы теряем

Часть возможностей настоящего git: подмодули, хуки, сложные слияния. Для заявленного
объёма (статус, дифф, коммит, ветки) этого не нужно, но обещать «полноценный git»
на этой основе нельзя.
