# ADR-001. UI-фреймворк: Kotlin + Compose Multiplatform

## Контекст

Нужны Android и Desktop из одного кода. Редактор, графическое окно и терминал в любом
случае рисуются самостоятельно, поэтому готовые компоненты фреймворка почти не помогают.
Главное же требование продукта — запускать нативные рантаймы (CPython, позже WASM) в своём
процессе и гонять кадры из натива на экран.

## Варианты

| | Рендер текста | Доступ к NDK | Зрелость на Android | Язык для владельца проекта |
|---|---|---|---|---|
| Compose MP | Skia, но два разных стека метрик | лучший (JNI родной для JVM) | высокая | Kotlin |
| Flutter | один стек на всех платформах | Dart FFI слабее для нашего случая | высокая | Dart — третий язык |
| Tauri v2 + web-UI | CodeMirror даёт готовый мощный редактор | Rust FFI хороший, но UI за WebView-мостом | мобильная часть моложе | Rust + TypeScript |
| Раздельные клиенты | идеально на Android | лучший | максимальная | удвоение работы |

## Решение

Kotlin + Compose Multiplatform.

Определяющий аргумент — не UI, а натив: JNI/NDK здесь лучше, чем у альтернатив, а вся суть
продукта в исполнении кода. UI-фреймворк выбирается под натив, а не наоборот.

## Последствия и цена

- Jewel (IntelliJ-подобные компоненты) существует только для Compose **Desktop**. На Android
  его нет, значит UI-кит пишем свой. Общий код будет в ядре и модели, а не в компонентах.
- Метрики и шейпинг текста на Android (`android.graphics`) и Desktop (Skiko) — разные стеки.
  Нужен собственный интерфейс измерения текста с двумя реализациями; расхождения в ширине
  глифов между платформами — ожидаемый класс багов, а не сюрприз.
- Compose Desktop тянет JVM в дистрибутив. На бюджет APK не влияет, на десктопный инсталлятор влияет.
- `material3` не подключаем: свой набор токенов честнее описывает нужды IDE и не тащит
  мегабайты компонентов, которые мы не рисуем.

## Что мы теряем

Готовый мощный редактор. Tauri + CodeMirror 6 дал бы rope, виртуализацию, мультикурсоры,
свёртку и инкрементальный парсинг бесплатно и годами отлаженными. Мы отказались, потому что
60 кадров в секунду из нативного процесса через WebView-мост — это борьба, а графика
заявлена ключевой фичей.

## Пересматривается, если

Прототип P2 покажет, что собственный рендер текста в Compose не держит 60 fps на телефоне.
